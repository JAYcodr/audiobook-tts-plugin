# 参考音频逐字文本

> 这份说明放在 `docs/` 而不是 `refs/`：发布包里的 `refs/` 只放 3 条 wav，
> npm 会强制收录任意目录下的 README*，放进去会被打包门禁判为多余文件（Issue #34）。

三条都是同一段**女声旁白**（说书腔、今昔感），只是截取长度不同。格式统一：
44100 Hz / 单声道 / 16 bit PCM WAV。侧车会自己重采样到 24 kHz，不用你转。

| 文件 | 时长 | 用途 | 相似度实测* |
|---|---|---|---|
| `narrator-14s.wav` | 14.20 s | **默认用这条**。完整句，断句自然 | 0.911 |
| `narrator-10s.wav` | 10.00 s | 想省一点加载时间的备选 | — |
| `narrator-5s.wav` | 5.00 s | 极限压缩；能听，但不如 14 s 稳 | 0.842 |

\* 同一参考音、同一段待测文本，用 CAM++ 算的音色相似度（开发时的评测数据）。
14 s 比 5 s 高约 7 个点，长句也更不容易在中途「换人」。

## 逐字文本（**必须一字不差**）

参考文本要和音频里**真的说出来的字**对齐。差一个字，音色就会飘，甚至读出怪音。
复制的时候注意省略号是中文的「……」两个字符一组的六点。

### `narrator-14s.wav`

```
我能隐隐约约感觉到，你和我一样，都有想要守护的东西……是那种，一步都不能退让，用尽一切办法都要守护的东西。
```

### `narrator-10s.wav`

```
我能隐隐约约感觉到，你和我一样，都有想要守护的东西，是那种，一步都不能退
```

### `narrator-5s.wav`

```
我能隐隐约约感觉到，你和我一样，都有想要守护
```

> 后两条的文本是**故意截断**的，不是打错——它们对应音频里被切掉的位置。
> 想要完整语义就用 14 s 那条。

## 用在哪里

### 本地引擎（`local` / `hybrid`）

控制台 →「渲染设置」→「本地引擎」→「参考音」：

```
旁白 wav    /绝对路径/refs/narrator-14s.wav
旁白 文本   上面 14 s 的那段
对话 wav    可以先用同一条
对话 文本    同上
```

只填旁白也能用：侧车发现 `dialogue` 缺失时会自动回退到旁白参考音
（`sidecar/server.py:134`）。想让对话听起来是另一个人，就再准备一条男声参考音，
用同样的格式和逐字文本。

### 云端克隆

MiMo 的 `mimo-v2.5-tts-voiceclone` 只要音频、**不要文本**（wav 转 base64，≤ 10 MB，
这三条都远小于这个数）。

插件里它出现在两个地方：

- **混合模式**：冷启动前几段用云端克隆顶住，用的就是「本地引擎 → 旁白参考音」
  这条路径，不需要另外配；
- **纯云端 + 克隆模式**：`voices.narrator.mode = "clone"`，此时
  `voices.narrator.voice` 必须是 **base64 data URL**，不是文件路径。
  控制台没有这个入口（界面只给 9 个预置音色），要手改 `config.json`——
  一般不推荐，纯云端直接用预置音色更省事。

## 自己录一条更好的

想换成自己的声音，注意这几点（都是踩过的坑）：

1. **5–15 秒**，一句完整的话，别含两段话中间夹长停顿
   （开发时有一条 4.76 s 的「两段话」参考音，两个引擎同时崩，文本识别错一半）。
2. **逐字写下来**，包括「的、了、呢」这些语气词和标点位置。
3. 44.1 kHz 或 48 kHz、单声道、16 bit WAV；不要混响、不要背景音乐、不要降噪降过头。
4. 语速和你希望整本书的语速接近——参考音的语速会被带进合成结果里。

验证方法很简单：拿新参考音合成一句，和原音频对比——
像不像你自己，耳朵一听就知道，不用看指标。
